# Requisitos No Funcionales del Sistema

## Rendimiento

| COD | Nombre | Descripción | Rol | Stakeholder |
|-----|--------|-------------|-----|-------------|
| RNF1 | capacidadUsuarios | El sistema debe soportar múltiples usuarios concurrentes sin presentar fallas en su funcionamiento. | Software | Estudiante |
| RNF12 | tiempoRespuesta | El sistema debe responder a las acciones del usuario en un tiempo menor a 3 segundos. | Software | Estudiante |

---

## Usabilidad

| COD | Nombre | Descripción | Rol | Stakeholder |
|-----|--------|-------------|-----|-------------|
| RNF2 | temaVisual | El sistema debe permitir la selección de tema visual (modo claro y modo oscuro). | Usuario | Estudiante |
| RNF4 | identidadInstitucional | El sistema debe utilizar los colores institucionales de la organización. | Software | Administrador |
| RNF6 | adaptabilidad | El sistema debe adaptarse a diferentes dispositivos como celulares, tablets y computadores. | Software | Estudiante |
| RNF9 | usabilidad | El sistema debe contar con una interfaz simple, intuitiva y fácil de usar. | Usuario | Estudiante |
| RNF14 | logoInstitucional | El sistema debe incluir el logo de la universidad en la interfaz. | Software | Administrador |

---

## Seguridad

| COD | Nombre | Descripción | Rol | Stakeholder |
|-----|--------|-------------|-----|-------------|
| RNF7 | seguridadContrasena | El sistema debe requerir contraseñas con una longitud mínima de 8 caracteres. | Software | Estudiante / Conductor / Administrador |
| RNF8 | tiempoInactividad | El sistema debe cerrar automáticamente la sesión del usuario después de un periodo de inactividad. | Software | Estudiante / Conductor |
| RNF11 | bloqueoIntentos | El sistema debe bloquear el acceso después de varios intentos fallidos de inicio de sesión. | Software | Estudiante / Conductor |

---
